# راه‌اندازی سامانهٔ لایسنس روی Cloudflare (بدون Wrangler)

این پوشه یک **سرور لایسنس + پنل مدیریت تحت وب** است که کاملاً روی Cloudflare
Workers اجرا می‌شود. تمام مراحل نصب فقط با کلیک در **سایت Cloudflare**
انجام می‌شود؛ هیچ خط فرمان (CLI)، هیچ Node.js و هیچ نصبی روی سیستم شما لازم نیست.

فقط به یک حساب کاربری رایگان در [dash.cloudflare.com](https://dash.cloudflare.com) نیاز دارید.

---

## مرحله ۱ — ساخت پایگاه‌داده D1

1. وارد داشبورد Cloudflare شوید.
2. از منوی سمت راست/چپ به بخش **Workers & Pages** بروید و روی زیرمنوی **D1 SQL Database** کلیک کنید.
3. روی **Create Database** بزنید. یک نام دلخواه مثل `study-scheduler-license-db` بدهید و بسازید.
4. وارد دیتابیس تازه‌ساخته‌شده شوید و به تب **Console** بروید.
5. کل محتوای فایل `schema.sql` (همین پوشه) را کپی و در کادر Console بچسبانید، سپس دکمهٔ اجرا (Execute/Run) را بزنید.
   - این کار دو جدول `licenses` و `activations` را می‌سازد.
   - اگر این مرحله را فراموش کنید هم مشکلی نیست؛ خود Worker در اولین اجرا جداول را می‌سازد.

---

## مرحله ۲ — ساخت Worker

1. به بخش **Workers & Pages** برگردید و روی **Create Application → Create Worker** کلیک کنید.
2. یک نام برای Worker انتخاب کنید، مثلاً `study-scheduler-license`، و روی **Deploy** بزنید (یک نسخهٔ پیش‌فرض ساخته می‌شود).
3. بعد از ساخته‌شدن، وارد صفحهٔ همان Worker شوید و روی **Edit Code** (ویرایشگر آنلاین) کلیک کنید.
4. تمام کد داخل ویرایشگر پیش‌فرض را پاک کنید و کل محتوای فایل `worker.js` (همین پوشه) را جای آن جای‌گذاری (Paste) کنید.
5. روی **Deploy** / **Save and Deploy** بزنید.

---

## مرحله ۳ — اتصال پایگاه‌داده به Worker

1. در صفحهٔ همان Worker به تب **Settings → Bindings** بروید.
2. گزینهٔ **Add Binding → D1 Database** را انتخاب کنید.
3. در قسمت **Variable name** دقیقاً بنویسید: `DB` (حروف بزرگ، این نام در کد استفاده شده است).
4. دیتابیسی که در مرحلهٔ ۱ ساختید را انتخاب و ذخیره کنید.

---

## مرحله ۴ — تنظیم متغیرهای ادمین

در همان تب **Settings → Variables and Secrets** سه مقدار زیر را به‌صورت **Secret** اضافه کنید
(گزینهٔ Encrypt/Secret را روشن نگه دارید تا در داشبورد قابل مشاهده نباشند):

| نام متغیر | مقدار |
|---|---|
| `ADMIN_USERNAME` | نام کاربری دلخواه شما برای ورود به پنل، مثلاً `abolfazl` |
| `ADMIN_PASSWORD` | یک رمز عبور قوی و دلخواه |
| `JWT_SECRET` | یک رشتهٔ تصادفی و بلند (حداقل ۳۲ کاراکتر) — می‌توانید از یک تولیدکنندهٔ رمز عبور آنلاین استفاده کنید |

بعد از افزودن هر سه مقدار، Save/Deploy کنید تا اعمال شوند.

---

## مرحله ۵ — تست پنل مدیریت

1. آدرس Worker شما چیزی شبیه این است: `https://study-scheduler-license.YOUR-SUBDOMAIN.workers.dev`
2. همین آدرس را در مرورگر باز کنید — صفحهٔ ورود پنل مدیریت باید نمایش داده شود.
3. با نام‌کاربری/رمزی که در مرحلهٔ ۴ تنظیم کردید وارد شوید.
4. از دکمهٔ «+ ساخت لایسنس جدید» یک کد لایسنس بسازید (یا کد دلخواه خودتان را وارد کنید).

اگر خواستید بعداً یک دامنهٔ اختصاصی (مثل `license.sitophil.com`) روی این Worker بگذارید،
از تب **Settings → Domains & Routes → Add Custom Domain** استفاده کنید (این هم کاملاً از سایت انجام می‌شود).

---

## مرحله ۶ — وصل‌کردن برنامهٔ ویندوزی به این آدرس

در برنامهٔ دسکتاپ (پوشهٔ `app/`)، فایل `app/core/config.py` یک مقدار ثابت به نام
`LICENSE_API_URL` دارد. آن را **قبل از ساخت exe** به آدرس Worker خودتان به‌علاوهٔ `/api/validate` تغییر دهید، مثلاً:

```
LICENSE_API_URL = "https://study-scheduler-license.YOUR-SUBDOMAIN.workers.dev/api/validate"
```

این آدرس عمداً داخل کد ثابت است: از داخل برنامه یا فایل‌های کنار exe (مثل `settings.json`)
قابل تغییر نیست و کاربر نهایی نمی‌تواند برنامه را به سرور دیگری وصل کند.

---

## نکات مهم

- **بدون هزینه برای شروع:** پلن رایگان Cloudflare Workers روزانه ۱۰۰٬۰۰۰ درخواست رایگان می‌دهد که برای این کاربرد کاملاً کافی است. D1 هم دارای سهمیهٔ رایگان سخاوتمندانه‌ای است.
- **هر لایسنس چند دستگاه؟** با فیلد «تعداد دستگاه مجاز» در پنل مشخص می‌شود (پیش‌فرض ۱). اگر مشتری کامپیوتر عوض کرد، از دکمهٔ «آزادسازی دستگاه‌ها» استفاده کنید تا بتواند دوباره فعال‌سازی کند.
- **غیرفعال‌سازی سریع:** برای متوقف‌کردن فوری یک مشتری، فقط دکمهٔ «غیرفعال کردن» را بزنید؛ در فعال‌سازی بعدی برنامه، خطای عدم اعتبار نمایش داده می‌شود.
- **کنترل در هر اجرا:** برنامه در هر بار اجرا از کاربر فعال‌سازی می‌خواهد (کد قبلی در فیلد پر است) و از سرور شما اعتبارسنجی می‌کند؛ پس غیرفعال‌کردن یک لایسنس از پنل، از اجرای بعدی اثر می‌گذارد.
- **روش جایگزین (اختیاری) با Wrangler:** اگر بعداً خواستید از GitHub برای دیپلوی خودکار استفاده کنید، فایل `wrangler.toml` همین پوشه آماده است؛ اما برای شروع به آن نیازی ندارید.
